# Data and failure semantics

## Time, units and identity

`Sample.timestamp_ns` and process `sampled_at_ns` are monotonic nanoseconds since that collector was constructed. They are not wall-clock values and cannot be compared across collector instances. Sequence zero means uninitialized. A caller can copy models to build snapshots; most hot getters borrow retained data and do no I/O. A refresh is an observation over a finite interval, not a kernel-wide atomic transaction.

CPU counters use kernel ticks. Aggregate/core utilization is `100 * delta_busy / delta_total`, with idle and iowait excluded from busy time. Guest time is already included in user/nice and is not added twice. Decreasing iowait or any other relevant counter invalidates the interval. Online CPU set changes invalidate aggregate utilization; unchanged core identities retain their own baselines. CPU frequency is an explicitly requested sysfs scaling frequency in Hz, not a guaranteed instantaneous hardware clock.

Process CPU usage is `100 * delta_cpu_ticks / (ticks_per_second * elapsed_seconds)`, measured between successful reads of the same `(PID, start_time_ticks)` identity. Linux can recycle PIDs; start ticks invalidate old state. Processes can use multiple cores and exceed 100%. Tick granularity makes very short intervals noisy; a zero increment is not proof that a task did no work. `ProcessId::start_time_since_boot()` converts ticks without losing subsecond precision; wall-clock conversion is deliberately not guessed.

Memory values are bytes. `used_bytes = total - available`, saturating at zero. Old kernels without `MemAvailable` use the documented free+buffers+cache+reclaimable-shared approximation and expose `available_is_estimate=true`. Process RSS from stat is the kernel's approximate resident page count times the actual system page size; it is not unique memory ownership. Swap counters are separate.

Diskstats sectors are always 512-byte accounting sectors, irrespective of physical block size. In-flight I/O is a gauge, not a cumulative value to subtract. Counter resets invalidate deltas. Partitions and whole devices overlap: summing both double-counts traffic. Device identity uses major/minor plus name; replacement entirely between samples with the same identity and nondecreasing counters cannot be detected. Network name reuse likewise needs explicit detail refresh to observe a changed interface index. Such unobservable replacement is a stated limitation, not a guarantee of perfect hotplug identity.

## Refresh scope and failures

`Processes::refresh()` enumerates before reconciling. If enumeration fails, the old table is not deleted. A successfully enumerated but unreadable PID retains a stale record with `Availability` and a failure entry; no fabricated zero data replaces it. PIDs absent from the completed scan are removed. `refresh_pid()` does not remove unrelated processes; vanished targets are removed and other errors mark the retained target stale. After an inaccessible interval, the next successful sample starts a new CPU baseline. `ProcessChanges.updated` includes new and reused PIDs; `added` and `reused` distinguish lifecycle events.

Details are never hidden inside ordinary stat refresh. Options independently select command line, executable and user/group IDs. `NotRequested` differs from `Unavailable(error)`. Executable and command-line bytes can change on exec without PID/start-time changes; details are a best-effort observation, not an atomic exec snapshot. An opened PID directory and before/after identity checks prevent metadata from a recycled PID being assigned to the previous identity. Raw command lines preserve NULs and non-UTF-8 arguments. Details do not change the retained process table's sample timestamp.

CPU, memory, network counters and disk I/O parse/validate before publishing a new snapshot. Malformed input retains old public data. Network addresses/link attributes have their own sampling time; refreshing counters does not make details fresh. A failed detail query does not undo a successful traffic sample. `System::refresh_basic()` refreshes CPU, memory, processes, network counters and disk I/O sequentially; if a later operation fails, earlier successful samples remain updated. This is intentional partial progress, not a transaction.

Mount discovery parses escaped kernel paths and mount IDs. Capacity queries are explicit because network/removable filesystems can block; the library provides no cancellation guarantee for synchronous `statvfs`. Failed capacity reads preserve the old value and timestamp while setting `last_error`. A reused mount ID only retains capacity state if root, device, path, filesystem type and source match. Callers needing isolation should query potentially blocking mounts in their own worker with bounded application policy.

Temperature/GPU discovery is opt-in and separate from sensor refresh. Missing attributes become `Attribute::Unavailable`; malformed or denied values become `Failed`, and legitimate zero readings remain `Value(0)`. Each hardware refresh records its attempted observation, including failures, rather than making old successful values look fresh. Kernel hwmon temperatures use millidegrees Celsius; GPU busy percentages and VRAM fields are driver-specific capabilities, not a universal vendor API. The library reads no control attributes and performs no clock/fan/power writes.

## Ownership and concurrency

Collectors require `&mut self` for refresh and expose borrowed or copied snapshots. There is no shared mutable global collection state, worker pool, lock, hidden thread or implicit sleep. Independent collectors can run on independent threads; sharing one collector requires the caller's synchronization. Temporary native allocations returned by `getifaddrs` are released by an RAII guard. Owned files close automatically. File/PID buffers grow to bounded read limits and are reused; topology changes and newly observed processes can allocate. On-demand details and topology discovery intentionally return/store owned data and can allocate. "Zero hot allocations" is a measured profile property, not a blanket API promise.

Core models/parsers do not require `std` or `alloc`. The Linux I/O backend uses `std` and native system ABI declarations with platform gates. Direct syscall numbers are enabled only for tested Linux LP64 x86-64/AArch64; other Linux architectures use the standard directory path. Windows/macOS builds expose the core but not `zsys::System`. Linux LP64 native structure layouts are checked both in Rust tests and against system C headers in CI; no generated bindings or third-party runtime crate is used.
